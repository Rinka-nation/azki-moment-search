本書は 2 つの内容を持ちます。4 章は**今あるテスト**の記録、5 章は**足りないテスト**の設計です。5.1 章（課題の再発防止）は 2026-11-11 にほぼ実装され、実装先を表の右端の列に書いています。5.2 章以降はまだ実装していません。

## 1. 方針

| 項目 | 内容 |
|---|---|
| ネットワーク | テストはネットワークに出ない（AGENTS.md）。YouTube、Turso、Vercel は偽物に置き換える |
| DB | 実物の SQLite + FTS5 を使う。`:memory:` または `tmp_path` |
| 辞書 | `accepted.toml` に左右されないよう、`include_accepted=False` の同梱辞書で試すものが多い |
| Sudachi | 実物を使う |
| 実データ | 使わない。`data/` に依存しない |
| 日付 | 「今日」を引数で渡し、日付で結果が変わらないようにする（`today=`） |
| 全件走査 | 検索の SQL を変えたら、実行計画で全件走査が無いことを確かめる（UT-071） |
| 読む行数 | `CLAUDE.md` の決まりで、検索の SQL を変えたら Turso の読み取り行数も測る。これはテストでは自動化されていない |

## 2. 実行方法

Python（`AZKiMomentSearch` で実行）:

```bash
.venv/Scripts/python -m pytest
```

Lint:

```bash
.venv/Scripts/ruff check src tests
```

Web（`web` で実行）:

```bash
npx vitest --run
```

型チェック（`web` で実行）:

```bash
npx vue-tsc --build
```

**注意:** 2026-11-02 の環境では、pytest の既定の一時フォルダ `%TEMP%\pytest-of-<ユーザー名>` が `PermissionError: [WinError 5]` になり、`tmp_path` を使うテストがエラーになりました。テストの問題ではなく環境の問題です（原因は未調査）。そのときは `--basetemp` で別のフォルダを指定すると全件通ります。2026-11-12 にも同じエラーが起き、`--basetemp` の指定で全件通りました。

```bash
.venv/Scripts/python -m pytest --basetemp=data/pytest_tmp -p no:cacheprovider
```

### 3.4 リスクの高い未テスト

壊れたときの影響で見た優先順位です。β版を公開しているので、公開側に影響するものを上にしています。

1. **`pipeline.build` の結合**: 全データの土台。除外配信を作らないこと、`meta` の目印、AI修正 の適用はここで組み合わさる（NT-003、5.3）
2. **`triage.classify`**: 補正の採否を自動で決める。誤ると `accepted.toml` に誤った補正が大量に入る（5.2）
3. **`App.vue` の残りの動作**: 件数の流用（`withCounts`）、検索の連打（5.8）
4. **`TursoPlatform`、`VercelCli`**: publish の外部とのやり取り。今は偽物で順序だけを確かめている

課題の対応で、`make_handler`（ISS-07、ISS-10）と横展開の読み込み（ISS-15）にはテストが入りました。
